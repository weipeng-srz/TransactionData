# TrendSight 手机体验测试方案

日期：2026-10-13。需求基准：[50 项产品说明](mobile-ux-product-spec.md)。结果写入 [验收记录](mobile-ux-acceptance.md)，本文定义操作与预期，不预填通过。

## 环境与证据

- 视口：320×740、390×844、430×932、820×1180；边界与桌面：821×1180、1024×768、1440×1000；短横屏补测 740×390。
- 状态：访客/已登录；浅色/深色；基础/专业视图；空态/有数据/加载/失败；系统减少动态开关。
- 本地使用仓库验证指南指定 Node，启动地址以实际 dev 输出为准。本次协调环境是 `http://localhost:3003`；不能把 URL 可访问当作所有功能已经体验。
- 每条记录必须包含需求 ID、环境、样本、操作、预期、实际、证据类型 S/A/B、结果与缺陷编号。`未执行`、`受阻` 与 `失败` 分开；没有数据不能写“通过”。
- 浏览器页面允许 DOM 测量和截图核验。源码字符串测试只能确认样式/契约存在；局部横滚还要实际滑到末项，输入还要实际操作。
- 使用隔离的本地测试身份和可控测试数据。不要为手机布局验证向生产账户写入持仓、复盘或密码。

## 桌面与领域回归门槛

- 对821/1024/1440的banner、主内容、子导航和主要表单记录变更前后同样状态的截图/DOM几何；本轮手机样式不得在桌面生效。若基线缺失，只能报告样式隔离检查，不能宣称像素完全相同。
- 搜索：CN与US、中文输入法合成、Enter、Escape、旧请求取消、错误重试；手机首次搜索CTA应能展开新的搜索面板，不能只focus隐藏input。
- 列表：自选/持仓切换、编辑打开与关闭、收益币种与月份选择；不应因为布局更改改变证券身份与统计口径。
- 复盘：草稿/完成校验、规则快照、保存确认、取消弹窗与未保存提示；CSS验证不能证明D1持久化成功。
- 账户：访客路由保护、next、错误和同步状态可见；不改身份隔离或冲突重试机制。
- 运行适用的lint/构建/已有移动布局、banner、导航、个股、选股、全球、复盘、账户测试；命令和结果以实际执行日志为准，不能把测试名称等同于覆盖范围。

## 缺陷闭环与最终产品验收

1. 测试发现问题，记录 `BUG-MOBILE-序号`、关联 M/T ID、复现步骤、实际/预期、证据和严重程度，立即通知研发。
2. 研发保留未提交基线，按 GitNexus 要求分析影响后修复；同一条缺陷附上修改位置。
3. 测试重跑原失败步骤与邻接状态，明确“已修复/仍失败/受阻”，不能仅凭研发描述关闭。
4. 产品按用户三项核心要求及50项清单复核；发布结论同时列出已验证范围和未验证限制。任何P0失败或桌面回归均不能写最终通过。
